# 消防报警系统联动逻辑配置与调试审阅平台

面向消防工程师、调试人员和审阅人的联动逻辑工作台，支持设备台账、因果矩阵、互锁/延时/优先级配置、矩阵校验、依赖图、版本差异、联调清单和签字锁定。

## 技术栈

Vue 3 + Vuetify + Pinia + Vue Router + Apollo Client + GraphQL + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62048`。

## 夜班挂牌与批次一致性

设备挂牌、因果规则和审阅批次共用同一份**依据（BASIS）**：

- 挂牌覆盖范围支持单设备 / 整分区 / 整楼层；范围一改，依据指纹立即推进，依赖它的规则立即失效重算——矩阵满足判定不再只看启停，挂牌覆盖的触发侧/动作侧判为未满足。
- 排烟风机、消防广播、电梯等**疏散动作**不被挂牌阻断，按签字锁定时固化的「已签优先级」继续执行，矩阵改动不改变疏散顺序。
- 两名调试员同时提交同一挂牌：**先到批次先占位先生效**，后到批次保留说明与冲突依据（先到批次号、先到依据、重叠设备），不覆盖；先到摘牌后可按原批次号续作。
- 挂牌/摘牌写入控制器可能失败：失败批次**按批次号从失败步骤续作**，不重新发号、不推进依据；失败期间保留批次占位以维持先到次序。
- 报警 / 复电回传**幂等**：重复回传只计数，已确认结果永远不会被改回待确认；复电回传可携带批次号触发续作。

场景验证（32 项断言，覆盖上述全部规则）：

```bash
npm run verify
```

## 核心工作流

- 按楼层分区维护探测器、模块和消防设备，建立触发到动作的因果矩阵。
- 配置延时、互锁、优先级和抑制条件，并批量启停或修改矩阵规则。
- 自动发现遗漏、重复、自相矛盾和跨区冲突，在依赖图中定位问题。
- 比较专业提交版本并部分接受变更，完成联调清单后签字锁定交付包。
